# Packaging and platform builds

The `desktop-matrix.yml` workflow runs Windows, Ubuntu 22.04 and macOS 14 builds in parallel and
uploads unsigned bundles. It is defined but has not been executed in this workspace. Each job runs
`tools/checksums.mjs` before upload. `desktop-release.yml` additionally builds Linux RPM and Flatpak
when a tag or manual release is created. Signing, notarisation and mobile jobs remain external.

## Current status

| Target | Artifact | Status |
| --- | --- | --- |
| Windows x64 | NSIS setup `.exe`, MSI, portable `KhaoyuNote.exe` | Built and tested locally |
| Linux x64 | AppImage, `.deb`, `.rpm`, portable `.tar.gz` | AppImage/deb/tar built locally; rpm comes from CI |
| macOS arm64 | unsigned `.dmg` | Matrix workflow defined, not yet executed |
| Flatpak | `.flatpak` | Manifest + CI job added; not yet verified locally |
| Android | APK/AAB | Not started, requires mobile port |
| iOS | TestFlight | Not started, requires macOS, Xcode and Apple account |

The local MCP server (`khaoyu-note-mcp`) is built. The Windows installers currently ship only the
desktop executable; the MCP binary is distributed as a separate file. Bundling it as a Tauri sidecar
is still open.

## Linux

The CI workflow installs `libwebkit2gtk-4.1-dev`, `libayatana-appindicator3-dev`, `librsvg2-dev`,
`patchelf`, `libxdo-dev`, `libssl-dev` and build tools, then runs `npx tauri build`.

Outputs:

- `src-tauri/target/release/bundle/appimage/*.AppImage`
- `src-tauri/target/release/bundle/deb/*.deb`

AppImage should be built on the oldest supported Ubuntu runner. Verify X11, Wayland, file drops and
open-with-default-app behaviour before release.

Final local 0.36.0 rebuild evidence (2026-11-12 20:33, Linux x86_64, Ubuntu 26.04 container):

- `Khaoyu-Note_0.36.0_amd64.deb` (6.28 MiB) built from the release binaries with Debian package metadata;
- `Khaoyu-Note_0.36.0_amd64.AppImage` (87.07 MiB) repacked from the bundled AppDir with the release binaries;
- `Khaoyu-Note_0.36.0_linux-x86_64.tar.gz` (7.83 MiB) contains the desktop and release MCP binaries,
  README, changelog and license;
- checksums are written to `dist/linux/SHA256SUMS.txt` and verified with `sha256sum -c`;
- the rebuild includes the final live-refresh, viewport and share-viewer web assets;
- runtime launch verification on X11 and Wayland (file drops, default-app opening) remains pending;
- Flatpak manifest is in `packaging/flatpak/com.dezuhan.khaoyunote.yml` and is built by the

- `desktop-release.yml` builds Linux `deb`, `rpm`, `AppImage`, Flatpak, Windows NSIS/MSI and macOS

## Flatpak

Flatpak is not generated by the Tauri bundler. `packaging/flatpak/com.dezuhan.khaoyunote.yml`
packages the prebuilt Tauri AppDir into a Flatpak using `org.gnome.Platform//50`. The
`Linux Flatpak` job in `desktop-release.yml` installs `flatpak-builder`, builds the manifest and
uploads the `.flatpak` bundle.

Do not publish the Flatpak until the CI job has produced it and the app has been tested for database
paths, asset storage, file drops and open-with-default-app under the sandbox. The complete
remaining-work list is in [blockers.md](blockers.md).

## macOS

The `desktop-matrix.yml` workflow builds an unsigned macOS arm64 DMG on `macos-14`. A universal
Apple Silicon plus Intel build is still a release gate. For notarisation, configure:

- `APPLE_CERTIFICATE`
- `APPLE_CERTIFICATE_PASSWORD`
- `APPLE_SIGNING_IDENTITY`
- `APPLE_ID`
- `APPLE_PASSWORD`
- `APPLE_TEAM_ID`

Without those secrets the build produces an unsigned DMG suitable only for development testing.
Verify the sandbox implications for file drops, assets and default-app opening before release.

## Android and iOS

Neither platform is part of the current desktop codebase. Tauri mobile support exists but the app needs:

- a touch interaction layer instead of hover toolbars and pointer-only drag;
- platform app-data directories for SQLite and assets;
- document pickers instead of native OS drag and drop;
- no stdio MCP binary on mobile;
- an explicit decision on whether mobile is a viewer, companion or full editor.

iOS additionally requires macOS runners, Xcode, provisioning profiles and App Store review. Do not promise
mobile artifacts until the desktop release is stable and the touch UI is designed.

## CI workflow

`.github/workflows/ci.yml` runs on every push, pull request and manual dispatch. It runs the web
static check and all Playwright suites on Ubuntu, and `cargo fmt --check`, Clippy with `-D warnings`,
the Rust tests and the MCP smoke suite on Windows.

`.github/workflows/desktop-release.yml` runs on manual dispatch and on `v*` tags. It builds:

- Windows x64 on `windows-latest`;
- Linux x64 on `ubuntu-24.04`;
- macOS universal on `macos-14`.

Artifacts are uploaded for 14 days. Signing secrets are optional; without them the macOS build is unsigned,
and Windows artifacts are unsigned unless a signing step is added.

## Release gates

1. All UI and MCP tests pass.
2. No open P0 or P1 defects.
3. Backup and restore verified on the target platform.
4. Version and changelog frozen.
5. Signing and notarisation complete where applicable.
6. Checksums published with every artifact.
7. Install, first launch, file drop, export and uninstall tested on a clean machine.

See `ROADMAP.md` Milestone 7 for the cross-platform release checklist.
